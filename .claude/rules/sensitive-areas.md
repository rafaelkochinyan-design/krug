# Sensitive areas — stop and ask before changing

For anything below, state the change and its impact, then **wait for the owner's explicit approval** before
editing. A reviewer treats an unapproved change here as a BLOCKER.

## Repository rules (from CLAUDE.md)

- Never merge to `main`, push to `main`, or deploy. Work goes through a PR and the owner merges.
- Never put secrets in code, commits, chat or logs. `.env.example` lists names only.
- Accounts, keys and billing belong to the owner. Never create or sign up for services on their behalf.

## Privacy and age

- **Other people see a member's name only** (later a photo). Never email, phone, `telegramChatId`, `city` or
  `adultConfirmedAt`.
  - Any response schema that includes other users (`members`, `organizerName`, anything new) must be reviewed
    for this, and must have a test asserting the absence of those fields.
  - The public invite preview (`GET /v1/invites/{code}`, no sign-in) shows the organizer's **first name only**
    (`firstName()` in `circles/service.ts`).
- **18+ only in v1.** `users.adultConfirmedAt` exists, but nothing enforces it yet. Any change to sign-up, join or
  create flows must consider it. Don't quietly weaken it.

## Auth (`apps/api/src/auth.ts`, `apps/api/src/config.ts`, `apps/app/src/lib/api.ts`, `apps/app/src/ui/DevUserBar.tsx`)

- `DEV_AUTH` / `x-dev-user-id` is **temporary** (removed in step 0.7, replaced by Better Auth).
  - Never widen it: no new ways to impersonate, no enabling it by default, no use from production code paths.
  - The production guard in `config.ts` (`DEV_AUTH` refused when `NODE_ENV=production`) must stay.
- `authRequired` must run before input validation on protected routes (401 before 400).
- Changing which routes are public (`GET /v1/invites/{code}`, `/health`, `/openapi.json`, `/docs` outside
  production) needs approval.

## Data integrity

- `joinByInvite` in `apps/api/src/modules/circles/service.ts` locks the circle row (`.for('update')`) inside a
  transaction so two people can't take the last spot. Never remove the lock or move the count outside the
  transaction.
- `createCircle`: circle + organizer membership + meetings are inserted in one transaction.
- **Applied migrations in `packages/db/drizzle/` are never edited.**
  - Schema changes are additive first. Destructive changes ship a release later.
  - Check constraints mirror `packages/domain/src/limits.ts` (weeks 1–16, capacity 3–20, weekday 1–7). Changing a
    limit means changing domain **and** adding a migration.

## Public contracts (phones keep old versions for months)

- `/v1` routes and their response shapes. Breaking changes need `/v2`.
- The invite link format `<APP_URL>/i/<code>` and the invite code format (10 chars, Crockford base32 in
  `packages/domain/src/invite.ts`). Codes already shared must keep working.
- The error envelope `{ error: { code, message, details } }` and the existing error codes.

## Generated and tooling files

- `packages/api-client/openapi.json` and `src/generated/schema.ts`: regenerate, never hand-edit.
- `packages/db/drizzle/**`: generated by `db:generate`, then reviewed.
- `.github/workflows/ci.yml`: changing or removing a check needs approval.
- `apps/app/app.json`: native identity (bundle id, scheme, plugins) is hard to change after the store release.
